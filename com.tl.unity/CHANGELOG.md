Newest first. Taken from the commit history since the zero-config plan started (`cbb7f14`). Short hashes name the commit.

## Unreleased

### Changed
- The pin is tl main `d286cdbb` (was `06a1c710`): Core gains `PlaybackImage` and `PlaybackTable.Save`/`Restore` (IAFahim/tl#681), which the Plain and .NET hosts use for exact rewind with kinds; the ECS tick does not use them. Core, Bake tools, the parity fixture and both generators resynced.
- The pin was tl main `06a1c710` (was `d87d1998`): dense kind picks, lazy-table stepping, the kind tick on `TlWorkers`, the Clock pack and the primary-constructor structs. Core, Bake tools, the parity fixture and both generators resynced; sv can move its vendored plain generator to the same commit (sv issue 0512).
- Fused precombined rows and precombined pulse tables (IAFahim/tl#662): precombined kinds in one system share one compact `KindValues` table and walk playbacks once with word-level `Active` mask updates, while `PrecombinedPulses` kinds evaluate pulses into `KindIndex.PulseValues` and apply fast 1x pulses directly from per-thread `KindPulseLane` hit buffers when `Playback` order version is unchanged (falling back cleanly to entry buffers on structural changes, disabled/partial rows, or unconsumed ticks). Unpinned `Precombined` / `PrecombinedPulses` kinds default to `[InternalBufferCapacity(0)]` to maximize chunk density (~3.6x fewer chunks at 1M entities) while `KindIndex.WorkerCache` caches archetype metadata per worker thread in `KindTickJob` and generated chunk jobs add `KindSlot_k` fallback support and single-lookup `GetComponentDataPtr`/`GetEnableableBits` access. Synced `Core`, `Editor/Bake/Tlb`, and generators to `tl` `1c17bda9`. PureShape with Burst (11 workers, 10,000-50,000 rows x 40-100 playbacks and 1,000,000 rows x 2-4 playbacks): 2.60x to 3.56x faster than `cd5189f` (`0.800-6.794 ms` and `6.878-9.045 ms`, zero warm allocation, hashes equal; 4 workers: `1.069-8.552 ms` and `9.317 ms`).
- Precombined spans (IAFahim/tl#655): a kind with `Associative = true` whose feeders take only the frame and their folds reads one precombined value per playback slot. The generated `Schedule` builds the table through `KindIndex.SpanValues` (Burst-safe, freed with the library); `Tests/KindsPure` hashes like tl's .NET KindShape pure domain. A kind that accepts only pulses no longer walks playback slots. `TLGEN115` is reported as info.
- Kinds read live spans from a load-time table (IAFahim/tl#652). `KindIndex.Score` lists, per (timeline, tick, kind), the span windows live at that tick; generated kind and feed jobs walk each row's playback slots and evaluate those spans, so the tick no longer appends or removes span entries and a row's entry buffers hold only pulses, game pulses and foreign ready values. A foreign feed job replaces its own earlier span values, so a feed that runs several times before its owner counts each span once. Generated jobs ignore copies that would lie past a row's `Playback` capacity. Rated playbacks are walked as one copy per crossing (`TimelinePlaying.Copies`). Last-wins kinds combine rated copies first (by source slot, then crossing), then the other slots in slot order, each in pair order (owner-approved; the parity fixture follows tl's re-pin). The lazy rows' entry cache (`KindEntryCache`, `KindTickStamp`, `StepOfEntry`, `PackedStep`, `WindowSteps`) is removed. Owner shape with Burst (500 timelines x 16 tracks, 11 workers): 3.8x to 4.7x faster at 10,000 to 50,000 rows x 40 to 100 playbacks, 3.1x to 3.2x at 1,000,000 rows; entity heap 21.5 KB to 1 KB per row at 100 playbacks; hashes equal.

### Fixed
- `ITlTrack` event methods (`OnClipStart`, `OnClipEnd`, `ExecuteActive`) raise for the ticks each step crossed, as on .NET (IAFahim/tl#665 row 8): they read the per-crossing copies the kinds apply, so every clip boundary and active tick is raised once at any speed, across a speed change too, and in the same step as its kind pulse. Before, they ran once per step at the last tick, so a boundary crossed earlier in a fast step raised no event. `ClipEventsAtEachSpeedRaiseWhatTheDotNetHostRaisesOnTheSameSteps` checks the per-step trace tl's `EventSpeedTests` pins at 0.5x, 1x, 1.5x, 2x, 2.5x, 3x and 4x.
- `Reset()` drops the game pulses queued for its object before the step (IAFahim/tl#604 U9), as `Reset(entity)` does on .NET and as the README says; they were merged after the tick and still applied to the new occupant.
- A declared `[TimelineSystem]` with events and no kinds of its own warns `TLUNITY9109` (IAFahim/tl#665 row 6): Unity does not run its event methods, and it said nothing. The warning says to move the consumers out of the struct, where the generated system runs them.
- A start of an id past the library is counted in `TimelineKindTick.DroppedStarts` (IAFahim/tl#665 row 7), so `TL_CHECKED` reports it; it was dropped without a count. A start of id 0 (a `Find` miss) stays a no-op, as on .NET.
- A Tl marker with no values is skipped with a warning naming its time and timeline (IAFahim/tl#665); it was dropped without a word, while an empty clip already warned.
- A kind that sets `FoldsPulses` now warns `TLUNITY9108` (IAFahim/tl#665): Unity does not fold game pulses, and the setting was ignored without a word. Queued game pulses to an object destroyed before the tick are dropped and counted (tested, IAFahim/tl#604 U9), and one job worker hashes like every worker across chunks (tested, U11).
- The kind tick applies one object's requests in slot order, as tl's .NET host and the kind-free path do (IAFahim/tl#604 U4). It applied them in the order they were added, so `Start(1, run)` followed by `Stop(0, run)` left `run` stopping on Unity and playing on .NET.
- `TimelineKindTick.DroppedStarts` counts every dropped start when several chunks drop starts at once (IAFahim/tl#604 U3); the parallel tick job incremented it without an atomic add.
- `TlFeedSystem` and `TlKindSystem` compile with `FloatMode.Strict` and `FloatPrecision.Standard` written out (IAFahim/tl#604 U5), as the kind jobs already did; they run kind `Combine` and feeder float math when they build the precombined tables. A test checks that no Burst code in the runtime or a generated kind assembly relaxes float math, and that Burst does not fuse `a * b - c`.
- The plain generator (`Tests/Plain/Generator/Tl.Gen.Plain.dll`) emits for a zero-config assembly, like tl's .NET generator and `Tl.Gen.Unity`: it runs when the assembly declares any clip track, kind, `[TlState]`, `[Feeds]` or `[Pulse]`, not only a `[TimelineSystem]`. Before, such an assembly got no `TlAuto_<Assembly>` unless it added an empty `[TimelineSystem]` struct (sv's tl glue carried one for this). `tests/Tl.Gen.Plain.Tests` pins its output to tl's .NET generator and runs on the `plain-generator` CI job.
- Compiles on the newest Unity 7, 7000.0.0a20 (#44): the generated type registration calls `UnityEngine.Internal.TypeManagerV2`, where a20 moved it; it failed with 192 `CS0234` errors before.
- World rewind moves playbacks of a library without kinds backward (IAFahim/tl#656): `TimelineAdvanceSystem` passes `TimelineStep.Forward` into `TimelineAdvanceJob` (new `Backward` field; `TimelineJobs.ScheduleAdvance` takes the direction). They kept advancing forward before.
- A start an object cannot hold no longer replaces the playback on its channel before it is dropped (tl `PlaybackRules.Start` checks the kinds first, IAFahim/tl#656).
- Kind-free libraries: a character could hold only 64 playbacks (`TimelineKernel.MaxSlotsPerEntity`), and further starts were dropped silently; it now holds 256, the same as Core and the kinds path. `TimelineRequestSystem` found each request's entity by scanning every requesting entity (quadratic in the number of characters that start timelines in one frame); it now uses a hash map (`79a099c`).
- tl `46f702d2` (IAFahim/tl#628 runtime fuzz): a rejected request batch no longer wedges the queue (#630); `TlWorkers(1)` runs every chunk before rethrowing (#629); a full 256-slot row refuses a channel replace instead of dropping both playbacks (#631); `KindStore` super-sampling keeps scratch slots on spill (#634) and grouped kinds sample once (#633) and remove only their own pulses (#632). The ECS kind tick was not affected (one buffer per kind; `KindCursor.Reserve` honours `used`); the fixes reach the copied Core and the generators.

### Added
- A UPM package of clips can opt into the Timeline **+** menu with `[assembly: Tl.Unity.TlMenuEntries]` (IAFahim/tl.unity#50). `TlMenuStubFiles` then writes `<Clip>_TlMenu` stubs for its clips like for clips under `Assets/` and `com.tl.pack.*`; before, clips in any other package never appeared in the menu.
- Other packages can read the Edit-mode preview (IAFahim/tl.unity#49):
  - `TlPreview.Evaluated` (multicast) is raised for every previewed director;
  - `TlPreview.Version(director)` changes when anything the preview reads changes;
  - `TlPreview.Record(director, readTick)` steps the Playable on the cached bake and calls `readTick` after every tick, then once for the state after the end.

  `com.tl.unity.ui` uses them to preview UI clips while scrubbing, in place of a copy of the private preview code.
- One control, event and pulse API with tl's .NET host (IAFahim/tl#656): `TlRequests` takes a library id (`ushort`) for every timeline verb next to `TlTimeline`, and `Reset()`; `TlLibrary.Find(name)` gives a timeline's id by its own name, also for timelines that streamed in late; `TlCheckedStartsSystem` throws on a dropped start when the scripting define `TL_CHECKED` is set. Cross-entity tests: a whistle on one row starts `stomp` on the row it aims at through a `BufferLookup<TimelineRequest>` job (ECS) and through `EventRecords.Of` (plain .NET host in Unity), with one shared hash. README 8.4 and chapter 11 list the verbs and the remaining host differences.
- Blending (IAFahim/tl#649, tl `ab483f68`): a `[TlClip]` struct that implements `IBlend<TClip>` crossfades where two of its clips overlap on one Tl track (factor 0 on the first tick of the overlap, 1 on the last, linear, 0.5 for a one-tick overlap; Unity's blend curves are not read). A clip without `IBlend` keeps the first clip during the overlap, as before. The generated frame helper calls the clip's `Blend`; track types, pair keys and bake bytes do not change. The host-parity fixture now carries a blending clip.
- Also Plays > **Play On Awake** (a toggle per timeline in the Playable Director's Tl foldout, off by default): the ticked timelines start when the scene loads, right after the Playable, at tick 0, in Also Plays order (not the order they were ticked), and also when the director does not play on awake (`TlAlsoPlays.PlayOnAwake`, baked as `TlAlsoPlayOnAwake` slots). The Playable ticked there starts at the director's Initial Time, like the director's own Play On Awake. Scene export lists them under `play`. The Timeline preview follows the director's own timeline (it followed the first playback, which could be an Also Plays timeline).
- Many At Once sample (README chapter 7): two timelines and two tracks on one platform, and a crossfade on one track.
- Lazy rows, third round: generated kind jobs resolve a span entry's library step once (cached in the entry when it is 16 B or wider) and inline `StepInWindow`'s fast path; lazy kind jobs at 20,000 rows x 200 playbacks went from 1.13 to about 0.88 ms per frame. Learned from reviewing BovineLabs Timeline and Core; their other ideas were measured or bounded and not taken (inline kind buffers 3 %, `[NoAlias]` columns 0 %, internals-based enable masks about 0.01 ms).
- Lazy rows, second round (IAFahim/tl#647 A3): the due scan runs 16 (AVX2) or 8 (SSE2) slots at a time; span kind entries cache their slot's stored tick and flag bits in their unused value bytes (`KindEntryCache`), kept current by the tick job, so generated kind jobs stop reading one random `Playback` slot per active clip whenever the chunk's `Playback` change version equals this frame's tick version (`KindIndex.TickStamp`, per world: the tick's system version and the identity of the index it ran with); enable bits are written through chunk `EnabledMask`s. Whole timeline frame at 20,000 rows x 200 playbacks, eager against lazy: 4.68 -> 2.46 ms (duration 120), 4.35 -> 1.69 (600), 4.48 -> 1.28 (3000); hashes equal. `KindHorizonTests` masks the cache bytes and checks every valid cache against its slot; a new law covers pause, resume, seek, reverse, stop, decoded edits, direction flips and limit changes.
- Lazy rows in the kind tick (IAFahim/tl#647 stage A3, tl `63d0d16d`): a row with `TimelineHorizon`, `TimelineClock` and a `PlaybackDue` buffer only touches the slots that change this tick. Ordinary slots store their tick relative to the row clock, each slot keeps the tick it is next due (next kind event or boundary from `KindIndex.Calm`), and due slots step with `KindRules.TickSlot`. Generated kind and feed jobs, `TlPanel` and the library swap read ticks through `TimelineTicks.Real`; `TimelineGlide { Limit = 0 }` decodes the rows back. Byte-identical to the full rules (pinned KindScript hashes; a 1500-tick differential at limits 1/7/255 through direction flips and glide on/off). At 20,000 rows x 100 to 200 playbacks of 1,000 kind timelines the tick job is 1.4x faster at duration 120, 3.3-3.4x at 600 and 10x at 3000 (11 workers, Burst). See `docs/KINDS.md` "Lazy rows".
- Horizon glide in the kind tick (tl `d0b77476`, `KindCalm`, `Horizon.OfKindRun`): `TimelineHorizon` (1 B per row) caches how many ticks are proven ordinary, so `TimelineKindTickSystem` only moves the tick between kind edges; `TimelineGlide { Limit }` on the system entity (default 255, 0 = off); `KindIndex.Calm` is built at library bind (2 B per timeline tick); invalidation by `ArchetypeChunk.DidChange` on `Playback`, library rebind, direction or limit change; `TimelineKindTick.ManagedRuns` and `KindCounter.ManagedRuns` Burst probes. On by default for baked directors and `TlSceneRun` rows; code-made archetypes add `TimelineHorizon`. Byte-identical to the full rules (pinned KindScript hashes, a 1500-tick differential at limits 1/7/255). See `docs/KINDS.md` "Horizon glide".
- Generated kind and feed jobs resolve a window that lies in one stage directly: `KindIndex.WindowStep` and `KindIndex.StepInWindow(timeline, window, tick)` replace the per-entry stage search, with the old search as fallback; `KindStepTests` checks it against the search on every tick.
